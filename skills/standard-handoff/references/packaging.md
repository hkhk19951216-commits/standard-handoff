# 打包、落盘与三档格式（可选手册）

仅在命中 zip / audit 档，或需要决定交接文件放哪时读本册。

## 三档产物（永远选最小够用）

| 档 | 结构 |
|---|---|
| `HANDOFF.md` | 单个 Markdown 文件，默认 |
| `handoff.zip` | `HANDOFF.md` + `attachments/` |
| 最小 audit | `HANDOFF.md` + `attachments/` + `MANIFEST.sha256`（覆盖包内文件的 sha256） |

**不做** LCH 式协议层：没有 `state.json`、`evidence/`、`verification/`、detached envelope、Receipt 对象、conformance 套件。最小 audit 只回答「包内字节有没有被改动」，不证明内容真实、来源可信、审批有效或语义连续。

判据只有一个：是否存在**下一步必需、且接收方通过共享工作区 / 已提交仓库 / 稳定授权位置拿不到**的文件。换窗口、换模型、换语言、换设备本身不升级格式；不要为了省事把整个工作区打包。用户显式指定格式优先，但缺件时标 `coverage: PARTIAL` 并在已知遗漏里点名，不偷偷覆盖用户决定。

## 附件规则

- 只放满足上述判据的文件，给出便携文件名，避免绝对路径。
- 每个 `attachments/` 里的路径必须在 `HANDOFF.md` 的「已知遗漏 / 开放问题」或「待完成事项」里逐字列出。
- 附件同样脱敏；不放大段日志、密钥、个人信息。
- 收包方把附件路径与文档描述对一遍，不一致先问，不猜。

## 落盘位置：把两个优点都拿到

冲突背景：一类做法写系统临时目录「不污染项目」，但临时目录会被系统清理、跨不了机器；另一类写项目根 `HANDOFF.md` 可 diff 可提交，却常静默覆盖旧文件、只靠 git 历史兜底。

本技能的规则：

1. **权威产物在工作区根 `./HANDOFF.md`**，可 diff、可提交、可跨机器；绝不写进任何 agent 配置目录。
2. **同名已存在**：默认另存带时间戳的 `HANDOFF.20261113-2150.md`，或先问「覆盖 / 另存 / 取消」。不静默覆盖，也不假设旧版一定能从 git 找回。
3. **系统临时目录只作 staging**：草稿、解压、校验中间态放临时目录，导出成功后清理；它丢了不影响权威产物。
4. 用户明确说「放临时目录、别碰工作区」时照办，但必须同时说明「此文件可能被系统清理，请及时取走」。
5. `AGENTS.md` 若要加自动读取规则：**追加**聚焦小节，不覆盖现有规则；可能冲突先问。本技能自身完全手动，不主动写 `AGENTS.md`。

## coverage 语义

- `FULL`：仅导出方在声明范围内没发现实质遗漏的主张。
- `PARTIAL`：有已知材料遗漏，必须在已知遗漏里写清。
- `UNKNOWN`：可访问的来源边界本身不清楚。

三者都只是声明，不是验证结论。

## 产物卫生与降级

默认成功导出只留**一个**最终文件。不留草稿 JSON、builder 脚本、staging 目录、解压目录、校验报告、checksum 文件、回执或被拒尝试，除非用户明确要调试或正式证据集。

汇报只给三样：格式选择句、最终文件链接、仅重大告警。不要倾倒包内文件清单或逐项检查结果。

附件打包或校验脚本不可用时，按同样的格式决策直接写 Markdown；**禁止模拟 hash、扫描、签名或验证**。明确说明哪一步没做，比编一个好看的结果诚实得多。
