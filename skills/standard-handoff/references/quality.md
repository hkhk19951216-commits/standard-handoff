# 质量分与校验器边界（可选手册）

仅在用户要求打分、复核交接质量、或需要解读校验结果时读本册。

## 0-100 质量分（人工判定，不写进产物）

四个维度各 25 分，低于 70 不要定稿：

| 维度 | 满分条件 |
|---|---|
| 结构 | 7 个固定标题齐全、各节非空、frontmatter 四字段填实 |
| 诚实 | 关键事实有可信度标记、UNKNOWN 没被补空、coverage 与实际相符 |
| 可执行 | 「下一步」第 1 条具体到路径或命令、不依赖隐藏上下文、不含破坏性动作 |
| 安全 | 八动词红线声明齐全、脱敏完成、无占位符残留 |

打分是给人看的沟通工具，**不是客观测量**，不要把它写进交接文档，也不要宣称「分数 X 所以一定没丢信息」。

## staleness 分级

按 frontmatter 的 `generated` 与当前日期之差：

| 级别 | 天数 | 处理 |
|---|---|---|
| `FRESH` | ≤7 | 正常读取，仍要复核易过期项 |
| `AGING` | 8–30 | 明确提示重验分支、测试、外部状态 |
| `STALE` | >30 | 只当线索，先重建当前状态再继续 |

「待完成事项」里的需重验条目没有观测时间或 `unknown` 时给 warning，不阻断。

## 校验器检查什么

`scripts/handoff_validate.py` 只读、不改写文件：

- 7 个固定标题各恰好出现一次且非空。
- 未解决占位符：尖括号占位、`TODO` / `FIXME` / `XXX` / `待填写` / `【待补】`。`TBD`、`待确认`、`UNKNOWN` **明确豁免**。
- 「下一步」编号第 1 条里的英文危险命令字面量（`rm -rf`、`Remove-Item`、`git push` / `rebase` / `reset --hard`、`git clean -f`、`DROP TABLE`、`ALTER TABLE`、全局安装包）。
- 密钥特征串（AWS key、私钥块、sk-/ghp_/xox 令牌、Bearer 值、明文 password 赋值）。
- 中文侧**不扫正文危险词**，改为检查「约束与风险」是否声明齐全八动词与「当前会话重新确认」句式。这是为了避免把「创建任务清单文档」「修改架构说明」这类正常描述误判成高危。
- `coverage: PARTIAL` 却没写已知遗漏 → 报错。

## 校验器不检查什么（重要）

不验事实真伪、不验置信度有没有被正确升级、不验语义连续性、不验来源真实性 / 署名 / 授权 / 审批，不计算或伪造 hash、扫描、签名结果，不宣称跨模型 / 跨语言 / 跨运行时 / 无损。**`PASS` 只说明结构与安全门过了，不代表下一步可以安全执行。**

脚本不可用时就直接写 Markdown，不要手写一个「看起来像通过了」的校验报告——伪造校验比没有校验更糟。

## 怎么读校验输出

`ERROR` 必须全部修掉；`WARNING` 逐条看，有正当理由可以保留并说明。退出码 0 = PASS、1 = FAIL、2 = 读不到文件或编码错误。输出前缀用 ASCII，消息可以中文。
